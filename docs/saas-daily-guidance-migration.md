用户已确认：**后端已经刷新并补齐历史记录的 `bodyContent`，旧版本缺失该字段的情况已由后端处理。** 不安排前端历史回填、批量数据迁移或重新确认补齐。四个列表接口现在不再返回正文；已有记录的编辑与独立模板预览须读取 `POST /dailyOrient/detail` 根字段 `body_content`。详情契约仍允许显式 null 或空对象，遇到这些值只读保护，不据此回填或覆盖记录。

## 2. 数据流与原字段契约

### 2.1 唯一正文与兼容字段

```text
新建空文档 / 已有记录 id → /dailyOrient/detail → body_content
                ↓
       对应公司模板内编辑
                ↓
         捕获同一正文快照
                ├─ 编码 bodyContent：完整正文与排版
                └─ 抽离原字段：原结构、原类型、原规范化规则
                                ↓
                   原保存接口 /dailyOrient/save
                                ↓
              沿用原成功处理，进入独立编辑器预览
                                ↓
                 只读正文 → 独立公司模板长图分享
```

完整正文是编辑和独立模板预览的唯一内容来源：读取新详情的 `body_content`，保存仍提交 `bodyContent`。原字段供现有业务继续使用，保存时必须和正文来自同一快照。四列表不再返回正文，列表和统计仍使用原字段；模板预览入口按记录 ID 判断可用性，不按列表有无 `bodyContent` 判断是否已填写。

不维护一套隐藏表单 Controller 作为第二正文源。可以提取原请求构造器的纯数据逻辑，以编辑器抽离结果代替表单值，保留其序列化行为。

### 2.2 提交字段以现有 SaaS 代码为准

基准为 `lib/modules/mutualism/presentation/orient_result/create/logic.dart` 的 `doneTask` 及内容构造方法、`lib/global/keys.dart` 的原字段常量。示例项目的 JSON、`GuidanceRecordFields` 或 Mock 不覆盖生产契约。

| 字段 | 保留的规则 |
|---|---|
| `id` | 沿用原身份规则：新建省略；原逻辑判断已有记录时提交其 `rootId`，不使用编辑器文档 ID 替代 |
| `orientType` | 当前记录的 `ORIENT` / `RESULT` |
| `bizType` | 分别为 `DAILY_ORIENT` / `DAILY_RESULT` |
| `dailyOrientContent` | 成果导向主栏目；只在 ORIENT 请求中提交 |
| `dailyResultContent` | 工作成果主栏目；只在 RESULT 请求中提交 |
| `thinking` | 感悟，沿用原内容对象；原逻辑为空时省略该字段 |
| `selfCheck` | 自检，沿用原内容对象；原逻辑为空时省略该字段 |
| `helpItems` | 全文各栏目中的都来帮条目，沿用原内容对象数组，按文档顺序汇总、跳过空条目，不添加 `sortNo`，不限制条数 |
| `navigatorItems` | 全文各栏目中的领航员条目，沿用原内容对象数组，规则同上 |
| `todoContent`、`expectedEffectContent` | 原请求均为 `{}`，保持不变 |
| `customData` | 当前原请求为 `{}`；没有既有格式依据时保持不变，自定义栏目完整保存于 `bodyContent` |
| `contentSnapshot` | 当前原请求为 `''`，保持不变 |
| `bodyContent` | 本次唯一新增的提交字段，保存编辑器完整正文快照 |

原内容对象仍为：

```json
{
  "content": "原字段对应的文字",
  "mentions": [
    {"userId": "用户ID", "userName": "用户名称"}
  ]
}
```

- 不把请求字段改成 `dailyOrient/dailyResult`。响应包装中出现的 `dailyOrient` 也不等于提交主内容字段。
- 不给另一种记录的主字段补 `null`，不新建顶层版本/hash 字段，不把响应中的未知字段整体回写。
- 旧字段的 `content` 沿用原 trim、首尾换行清理、末尾真实用户提及补空格等规则（原实现保留段间换行）；完整换行、样式和块结构保留在 `bodyContent`。
- 原 `mentions` 仍只承载用户，保留 `userId/userName`。编辑器内部引用属性不直接成为旧字段格式；任务、会议、文档身份不能冒充用户 ID。
- 不从 example 直接搬用包含 `dailyOrient/dailyResult`、`sortNo`、三字段 mentions 或新 `customData` 结构的请求结果。可复用正文遍历能力，另写 SaaS 原字段适配器。

### 2.3 栏目抽离边界

| 编辑器内容 | 对应原字段 |
|---|---|
| 当前类型的主栏目正文（含其中的都来帮、领航员内容） | `dailyOrientContent` 或 `dailyResultContent` |
| 感悟栏目正文（含其中的都来帮、领航员内容） | `thinking` |
| 自检栏目正文（含其中的都来帮、领航员内容） | `selfCheck` |
| 任意栏目中的都来帮业务条目 | 在保留来源栏目内容的同时汇总到 `helpItems` |
| 任意栏目中的领航员业务条目 | 在保留来源栏目内容的同时汇总到 `navigatorItems` |
| 自定义栏目 | 完整保留在 `bodyContent`；不自行扩展原 `customData` 协议 |
| 模板标题、问候、日期、装饰、Logo | 不抽离为业务正文 |

后端实际 `daily-writing` v5 含嵌套 `daily-body`、锁定标题及无行内标签的 `dailySection=help/navigator` 区域。读取须保留原嵌套区域、稳定 ID、属性及锁定标题，编辑投影不能把树拍平后覆盖源正文。主字段仅收当前主正文；`daily-body` 下的独立 todo/expected-effect/help/navigator 区域不混入主字段。另一类型的 `legacy-orient/legacy-result` 独立保留，不能混入当前主字段或感悟/自检。

原表单生成的 `todo/expected-effect` 若仅含模板标题和空白普通段落，不向编辑器投影空输入区，原区域仍完整保存在正文源树；若含正文、人员提及或复选项，分别独立显示“要做的事 / 预期效果”，不得伪装成主正文。未修改时区域、块 ID、元数据和隐藏状态无损往返；新增主正文段落必须归属当前主字段，不继承历史空区。历史栏目的内部标识（包括 todo/expected-effect 和另一类型 legacy-orient/legacy-result）必须避让真实自定义字段，保留真实字段标识、标题和隐藏状态；嵌套区域继承避让后的归属，不通过保留字限制已有后端数据。`todoContent/expectedEffectContent` 仍按原接口约定提交 `{}`。

抽离不改变编辑器中的位置或内容。隐藏栏目保留的内容仍属于正文，关闭展示不等于删除数据；实际删除后按原提交语义生成字段。预览仅按文档位置渲染，不在正文下再重复拼接原摘要数组。

**跨栏目保留与聚合同时执行。** 遍历主栏目、感悟、自检、自定义栏目等全部正文，识别实际 help/pilot 业务标记，将都来帮汇总到 `helpItems`、领航员汇总到 `navigatorItems`，不从来源栏目移除文字、引用或块结构。

- 来源栏目有对应原字段时，该字段继续包含条目内容及其用户 mentions；同一条目也进入对应数组。自定义栏目仍完整保存在 `bodyContent`，其中的业务条目同样进入数组，不另造 `customData` 格式。
- 两个数组各自按全文文档顺序生成；每个实际条目在对应数组中出现一次，不因来源栏目抽离与全文聚合重复收集。不同条目即使文字或人员相同也不全局合并。
- 业务标记同时支持行内 `dailyTag=help/pilot` 与后端祖先区域 `dailySection=help/navigator`，同一行只收集一次；不把普通文字中的“都来帮”或“领航员”当作条目。空条目不生成数组项，其正文按既有保留规则处理。
- 来源字段与数组项都使用原 `{content, mentions: [{userId, userName}]}` 结构及规范化规则。隐藏但保留内容的栏目同样参与抽离，实际删除的条目不再聚合。
- 例如感悟中有一条都来帮：`thinking` 保留完整感悟和该条内容，`helpItems` 同时包含该条；编辑、预览和分享仍只在其原文档位置显示一次。

### 2.4 解除字数和条数限制

新编辑器不迁入原表单的主内容 30 字、感悟/自检 300 字、都来帮/领航员单条 50 字及各最多 3 条限制；字数限制也不保留原保存校验中的最少 5 字要求。主内容非空、中文要求、权限和填写时间窗等非计数规则继续沿用。

手动输入、粘贴、添加条目、正文加载、抽离、保存及重开均不能重新套用这些限制，不截断正文、原字段或数组，也不因超过原上限拒绝已有正文。两类记录、新编辑器各公司模板和各栏目使用同一规则；共存的原表单不在本次解除限制。

实现时用超出原边界的内容验证原接口回读与长图容量；如果实际遇到传输或资源容量错误，应保留草稿并明确反馈，不以恢复旧表单限制或静默裁剪作为处理方式。

## 3. 创建、编辑、保存与重开

### 创建

1. 沿用原创建入口的类型、账号、企业、业务日和权限上下文，生成对应类型的空编辑文档。
2. 选择公司模板编辑时，根据公司 ID 和作者部门匹配[覆盖清单](../../cses/cses.saas/saas-company-template-coverage.md)中的独立视觉。未匹配到专属编辑器模板的公司从原七套公共模板中随机选择。选择原表单时继续走原路由。公司身份在入口捕获并固定，创建、详情编辑、预览和保存重开使用同一解析规则。
3. 保存前结束输入合成，捕获正文快照，按第 2 节保留来源栏目并聚合业务条目，执行解除字数和条数限制后的业务校验。
4. 调用原保存用例，原请求追加 `bodyContent`。保留原成功/失败判定、刷新事件、返回结果和预览导航。
5. 保存成功后冻结当前编辑会话，按返回的正式记录 ID 读取新详情，预览使用通过校验的读回正文。保存失败保留草稿；保存成功但读取失败明确提示已保存，仅重试读取，不能重复提交，退出仍返回保存成功。不得把 example 本地保存成功视为 SaaS 保存成功。

### 编辑已有记录

1. 使用被点击 ORIENT/RESULT 槽位的真实记录 `id` 请求 `POST /dailyOrient/detail`，只传裁剪首尾空白后的 `id`；不用列表父记录、`rootId`、用户、模板或正文根 ID 替代。无 ID 的槽位禁用详情入口，空白 ID 不发请求；新建无 ID 的编辑流程仍可创建内存空文档。
2. 进入已有记录编辑或独立模板预览时先加载详情，加载完成前不创建可写会话。HTTP 200 且根 `isSuccess:true` 才成功；失败展示错误及重试，不使用旧列表正文或另一条记录回退，也不调用旧平台详情接口降级。
3. 详情从根 `body_content` 读取。独立 DTO/实体完整保留 26 个业务字段及所有 JSON 列中的未知属性、显式 null、空容器和顺序，不经列表 Bean/ContentBody 清理，不递归转换正文键名。来源列表的行为统计单独保留，不能被详情缺省字段清零。
4. 宿主校验返回的记录、公司、作者、类型与原入口上下文，继续遵循原编辑权限、业务日和填写时间窗。详情成功且正文受支持后，才创建当前页面唯一活动会话。读取允许查看历史或他人记录，不代表可编辑。
5. 请求期间切换记录、公司、账号或退出页面后，旧结果及错误不得打开旧正文或替换新状态；重试使用独立请求代次。已有未保存输入不被后台刷新覆盖。
6. 保存仍从同一快照生成完整正文及原字段，经原保存接口提交。确认成功后按详情接口文档重读同一记录并刷新来源列表；保存失败保留输入。读取失败与提交失败分开，前者仅重试详情、禁用分享，不再次提交；已有记录未修改时直接读回，不产生额外保存请求。重开再次读取详情，不信任入口携带的旧正文。

后端已处理历史缺失数据，前端不增加历史迁移分支。详情 `body_content:null` 显示“暂无完整正文”；空对象、格式损坏或当前不支持的文档显示“正文暂无法展示，请更新页面后重试”。两者均保留本次详情的原内容字段供只读查看，禁用会覆盖正文的编辑和保存，不自动生成空文档。这是读取边界保护，不是历史数据迁移。

填写时间窗、历史编辑权限、主内容非空及中文校验、保存完成事件、刷新、待办和分享回写均沿用现有逻辑。原字数和条数限制按第 2.4 节解除，不保留最少字数校验，也不静默截断正文或抽离数组。

### 4.3 全部公司模板共用的高度规则

**编辑态**上方主图固定为原模板在当前宽度下的最小高度，不随正文长短、屏幕剩余空间或键盘弹出而增高；Logo 隐藏。短文由最后一个可见栏目的纸张和装饰横格补齐当前可用书写视口。前置栏目按自然高度排版，长文自然滚动。横格随键盘、工具栏、栏目和文字缩放变化重新分配，仅用于显示，不生成正文节点或改写 JSON。

**预览和分享长图**使用相同已保存正文、图片取景、宽度及手机屏高基准。先用原模板最小主图测出自然画布：

```text
自然画布高度 = 上方模板高度（主图取原版最小值，含原有装饰与间距）
             + 编辑器正文自然高度 + 满宽 Logo 按原比例得到的高度
主图增加高度 = max(0, 手机完整屏幕高度 - 自然画布高度)
最终主图高度 = 原模板最小主图高度 + 主图增加高度
最终画布高度 = max(手机完整屏幕高度, 自然画布高度)
```

- 短文的缺口全部由主图增加高度补齐；正文、Logo 及其原有必要间距不拉伸、不添加占位。长文不再增加主图高度，正文与整张长图自然增长，不能为了固定画布裁掉内容。
- 正文按现有只读渲染规则取自然高度，不新增空行、横线、固定正文空白或最小正文高度来填屏。正文结构、用户换行、空段和样式完整保留在 `bodyContent`；沿用现有只读渲染规则，包括栏末纯空段的折叠显示，布局不新增、删除或改写正文 JSON。
- 手机完整屏高是画布的下限，不扣固定操作栏高度；固定栏、系统操作层及为底部安全防遮挡设置的尾距在画布外，也不能拿来抵扣短文缺口。原模板自身的顶部安全区仍按模板构图计入上方模板，不与画布外尾距混算。
- 保留原图裁剪和取景组件、日期、问候及装饰的构图规则；主图增加的是容器高度，图片继续按原裁剪方式展示，不拉伸原图或另造图片手势。预览与截图共用最终高度和取景，截图不包含画布外的固定栏或防遮挡尾距。

该规则适用于纳入迁移范围的动态公司模板、部门、变体与兜底模板。固定异形主图的短文补高策略须单独确认。

## 7. 验证与完成条件

- **原请求兼容**：升级请求除 `bodyContent` 外，保持原字段名、类型、内容对象结构和规范化规则；字段值按第 2.3 节抽离，不把新增跨栏目聚合误判为协议变化。覆盖两类记录、创建/修改身份、空选填、数组顺序和真实用户提及。
- **解除限制**：覆盖主内容超过 30 字、感悟/自检超过 300 字、业务条目超过 50 字及每类超过 3 条，验证输入、粘贴、抽离、保存、重开和分享完整。少于 5 字但满足非空/中文规则的主内容也能通过校验。
- **跨栏目聚合**：在主栏目、感悟、自检及自定义栏目混合放置都来帮/领航员，检查来源正文和对应原字段保留完整、两数组分别按文档顺序收集且每个实际条目只收集一次；覆盖同文不同条目、隐藏恢复、删除、用户 mentions、重开和只渲染一次。
- **正文往返**：保存后重开按记录 ID 重新读取详情，保留正文、栏目、样式和引用；验证根 `body_content` 与保存 `bodyContent` 的独立协议。确认保存后重读同一详情并按原事件刷新来源列表，不重新把历史补齐列成未决事项。
- **详情入口**：四个列表均无正文时，ORIENT/RESULT 的编辑和模板预览仍按各自 ID 加载；覆盖空白 ID、200 业务失败、登录失效、网络错误与重试。null/空对象/不支持文档仅只读原字段；切换记录、公司、账号、页面销毁及请求乱序后，旧结果不得创建会话或覆盖当前内容。
- **同源保存**：中文合成结束后保存，正文与旧字段来自同一快照。保存失败不丢草稿、不提前执行原成功行为。
- **动态栏目**：感悟、自检、都来帮、领航员及自定义栏目添加、填写、关闭、恢复、撤销和重开可用；清空选填内容后检查原消费端是否保留了旧值。
- **原业务保持**：原表单与旧模板流程继续可用；新编辑器原权限、非空/中文校验、刷新和返回流程继续生效，字数/条数限制按已确认规则解除；列表与统计仍消费原字段，包括跨栏目聚合后的数组。原模块复制、互动等不因新字段解析而改变。
- **模板与长图**：每个可达模板以相同图片来源、取景、宽度、作者、时间和正文快照对照原版。正文自然高度及已确认的主图补高、顶部、Logo 和头像边框差异单独标注，其余区域核对素材、几何和图层。分别覆盖短文、临界一屏和长文：编辑主图保持最小高度，短文末栏用横格铺满可用书写视口；预览与 PNG 完整画布至少一屏，短文只由主图补高，只读正文自然排版，JSON 前后不变；操作栏与防遮挡尾距不入画布。键盘开合不能增高编辑主图，短文与长文预览、截图的高度和取景一致。
- **真机**：Android 首批跑中企云链及两类记录，后续再覆盖其他模板，检查长文、中文键盘、菜单切换、整体滚动、顶部悬浮按钮、保存、重开和长图完整性。其他平台与模板按实际范围记录，不以 example 截图代替 SaaS 验收。
- **宿主复用**：`@`、都来帮和领航员均打开 SaaS 原人员选择器；覆盖单选、多选、搜索、取消、身份失效及选人期间原目标变化。确认/输入弹窗不再包含 example 的重复外壳。
- **代码质量**：格式化手写文件，在所属包分析并运行目标测试；公开 API 或依赖变化验证消费者；执行 `git diff --check`，验证证据归档并更新索引。

测试优先覆盖新的字段适配、正文解析与往返、会话/测量和模板渲染，不为未改的列表、统计业务新增重复实现的测试。已有回归继续执行。
