# SaaS 日填写旧主区保存与回读

## 真机定位

从 Android 当前报错页面的调试会话读取其详情快照，确认正文版本为 v5，根节点只有一个带 `dailySlot: daily-cover` 的填写区。该区没有 `dailySection`，也没有并列的 `daily-body`。重试时在发送请求之前检查保存前快照，确认顶层区块 ID 和 `daily-cover` 标记与原始详情一致，标准主区匹配数为 0。设备用于定位，原记录未产生新的保存请求。

## 兼容与验证

- 按 [跨端正文合同第 8 节](../../../../cses/cses.saas/daily-fill-mobile-pc-body-content-contract.md#8-手机端写入要求) 补齐既有主区的两个 v9 标记及布局元数据。没有标准主区时，唯一且未标为其他业务栏目的旧封面填写区沿用自己的区块 ID 原位升级。有效的标准主区优先，存在多个旧区且无法确认归属时提示格式错误。
- 新增页面回归用测试仓库模拟同一条 v5 记录的详情、保存和再次读取。修复前复现主填写区错误。修复后验证只提交一次、按原业务 ID 回读、预览展示修改后的文字，日期区符合规范，原区块及段落 ID 和合法扩展字段保留。
- 新增规范化测试覆盖标准主区与旧封面区并存，以及多个旧封面区来源有歧义的情况。
- 在 SaaS 包格式化三个手写 Dart 文件，目标静态分析通过。
- 单独复跑两项新增回归，全部通过。
- 四个相关测试文件共通过 184 项，另有一项同时开发中的划词任务表单测试在查找菜单按钮时失败，发生于正文保存之前。
- SaaS 与编辑器仓库的 `git diff --check` 均通过。
