# 今日导向图片分享（2026-10-30）

## 行为

点击预览页分享后，打开图片生成与分享预览页。使用原页面宽度及同一正文渲染器，对独立只读文档快照一次排版完整内容；保留封面、宿主用户、日期与末行正文，尾部附 `assets/images/中企云链_logo.png`（含 slogan）。截图不包含状态栏、返回、分享、点赞或分享操作栏。

图片可纵向查看，底部固定微信、朋友圈、保存图片及取消。分享操作期间防重入；结果和错误在操作栏内展示，不遮挡取消。原预览滚动位置、点赞状态和正文不变，不保存草稿；没有恢复滚动隐藏按钮。

## 实现与平台边界

- `JournalSharePage` 拥有独立编辑器，视图卸载后关闭；PNG 转码后释放原始图像，退出页面后内存随路由回收。生成期间等待资源加载，限制像素总量和最长边，超长内容明确提示失败，不静默截尾。
- 完整截图布局仅在传入 `JournalSurface.captureKey` 时启用，普通预览维持既有滚动路径。根包、块协议和 AppFlowy 来源均未修改。
- `LocalJournalPage.imageActions` 支持宿主注入，无账号/全局服务兜底。每次异步完成和目标操作前复核原页面、账号与文档；失效时拒绝分享，迟到回调不显示成功。
- Android 使用当前应用临时目录 PNG，通过只授权该目录的 FileProvider 交给微信；朋友圈尝试微信现有图片入口。未安装微信或入口不兼容会明确提示保存后分享，不冒充发送成功。临时文件超过一天后在下次分享时清理。
- iOS 使用系统图片分享面板，用户在面板中选择微信或朋友圈，不借用参考项目的微信 AppID、签名或 SDK。页面会明确提示系统选择流程。
- 保存图片使用已有 file_picker 系统保存框，默认 PNG 文件名与 MIME；用户取消不提示保存成功。不是静默写入相册。
- iOS 示例最低版本调整为 14，以满足仓库已有 file-picker-darwin 的平台要求。参考仓库只读借鉴流程，没有引入路径依赖或 Common SDK。
