# SaaS 保存异常、退出保护与异步返回 Android 验收

日期：2026-11-08；设备：Honor MTN_AN00；宿主：cses.jqdl 测试环境；记录：现有工作成果 RESULT 测试记录；模板：当前今企合力公司正式分发的中企云链兼容模板。

## 验收结果

保存失败、保存成功后详情读取失败、重复保存、未保存退出和迟到异步返回的数据保护通过。期间发现并修复一个实际问题：原人员选择器取消后仍显示划词浮层，此时打开退出确认会触发构建期权限通知断言。新增回归先稳定失败，修复后通过；最终 Android 复测结果见下文。

本轮只更新 SaaS 退出交互、对应测试、模块说明及验收记录；没有改原表单、原公司模板、请求协议、根编辑器或 AppFlowy fork，没有提交代码。

## 真实保存失败与恢复

1. 从工作成果入口读取已有详情，在自定义栏普通文字后追加 FAIL-SAVE-A1；关闭手机 Wi-Fi 与移动数据，点击保存。
2. 页面显示“保存失败，请重试”，未进入预览；草稿完整保留，可继续追加 RETRY-B1。
3. 返回时选择“继续编辑”，草稿仍保留；再返回选择“保存后离开”，断网提交失败仍留在原编辑页。
4. 恢复网络后提交成功；两个标记均进入同一次正式请求，后续详情正文与成功请求完全相等。
5. 共记录 4 次保存传输失败：断网保存、断网离开保存各一次，另两次发生在网络刚开启但尚未连通时。它们均快速结束，没有成功写入回执；不能据此误判为同一在途操作重复提交。

证据：[失败后正文保留](offline-draft-preserved.png)、[分阶段请求核对](http-checks.json)。

## 保存成功后详情失败与重复操作

- 使用标准 Dart 调试断点，在 Store 已确认保存成功、准备调用正式详情用例时暂停；此时关闭网络，再移除断点并恢复运行。没有伪造成功响应或替换接口数据。
- 页面明确显示“已保存，预览读取失败”，不提供再次保存入口，分享和换图动作禁用。
- 恢复网络后连续点击“重试读取”，只增加 **1 次成功详情请求、0 次保存请求**；正式正文与成功提交快照完全一致。
- 网络已连通时连续点击保存，仅有 **1 次成功保存**。自动化另用未完成的真实页面提交 Future 稳定覆盖“等待回执期间再次点击”，确保执行锁持续有效。
- 无修改重开后进入预览，只读取详情，没有额外保存。

证据：[已保存但详情失败](saved-detail-failed.png)、[独立复核](independent-checks.json)。

## 未保存退出

- “继续编辑”和“取消”均保留当前本地修改，没有新增保存。
- 加入 DISCARD-C1 后选择“放弃修改”，重开正文与上一份已保存正文相等，不含该标记，也没有新增保存请求。
- “保存后离开”失败留页和恢复输入由真机验证；其失败后继续修改并成功离开的完整路径由页面回归测试覆盖。
- 通过真实编辑操作清理 FAIL-SAVE-A1、RETRY-B1 并保存，最终请求和重开详情的完整正文均恢复到本轮验收前 baseline。原正文、感悟、自定义栏目普通内容及先前清空的数组状态保持。

证据：[原公共退出选择器](unsaved-exit-dialog.png)、[清理前后正文一致性](http-checks.json)。

## 异步返回的可控真机验证

为稳定覆盖“离开在先、结果返回在后”，仅在调试会话中，将真实接口/原人员选择器/原随机图结果交还页面的时机延迟 25 秒；原 mounted、会话、文档守卫完全保留。返回数据未更改，延时不属于最终实现。临时源码先精确恢复，再实施独立退出修复；正式 APK 重新构建安装，不包含延时或断点。

| 返回来源 | 真机时序 | 结果 |
| --- | --- | --- |
| 初始详情 | 加载中取消，进入原列表，再接收旧详情 | 原页面 mounted=false，列表保持，不重新挂编辑器 |
| 原人员选择器 | 选中两名成员，完成后在返回值送达前放弃修改，再重开 | 旧页面 mounted=false，两名成员没有写入新会话或后台 |
| 保存后详情 | 清理内容已保存，读回结果暂缓时取消预览并重开 | 已保存身份保留，旧页 mounted=false，不重建旧预览或重复保存 |
| 随机图 | 原随机图结果暂缓时取消预览，打开新预览，再接收旧结果 | 旧页 mounted=false，新预览图片没有被替换，正文零写入 |

初始详情另有一次 mounted=true，属于新页面正常接收，不能把所有返回一概视为丢弃。不同路由会按原流程随机取得初始主图，因此图片证据比较的是**同一新预览**在旧结果释放前后，而不是两个路由的初始图片。

原人员页另验证了切到后台再恢复、取消后只保留空业务行。身份撤销、公司/文档变化及图库取消的组合边界由现有目标测试覆盖；真机没有切换其他公司或账号。

证据：[脱敏延时阶段](async-phases.json)、[列表未被旧详情替换](late-entry-stays-list.png)、[新会话无旧人员](late-people-new-session.png)、[旧图片返回前](new-preview-before-late-image.png)、[旧图片返回后](new-preview-after-late-image.png)。

## 发现的问题与修复

问题最初在调试热重载时观察到，随后未注入故障的正式 APK 冷启动以及真实浮层 Widget 测试均稳定复现，确认为产品问题，而非仅调试干扰。

触发：原人员选择取消 → 键盘/“粘贴、全选”划词浮层恢复 → 顶部返回 → 退出确认。原实现先重建临时只读正文，AppFlowyEditor 初始化过程中才修改 editable，导致仍挂在 Overlay 上的划词浮层在构建阶段收到通知，报 `setState() or markNeedsBuild() called during build`。

修复：SaasGuidanceEditorPage._leave 在交互事件中先同步关闭正文输入权限、收起键盘和焦点，再设置退出状态。确认取消/继续编辑仍先恢复权限、再恢复编辑布局，不清空原选区、不改变保存流程。

- [本轮生产代码最小补丁](exit-overlay-fix.patch)。
- [修复前失败输出摘录](regression-before-excerpt.txt)：明确为工具输出摘录，不冒充完整原始运行日志。
- 新增真实 MobileFloatingToolbar 回归覆盖“选人取消 → 划词浮层出现 → 返回 → 继续编辑”，先失败后通过；没有用伪造的监听组件代替。

## 修复后正式 APK

修复后的正式 debug APK 构建成功并冷启动安装到同一 Android 手机；本段没有热重载、临时延时或调试断点。APK SHA-256：`dd9a2a44a022a1e8bdb0a8fe7e5535359e0443b65ee6e1126628391766d0251d`。

1. 原领航员选择器取消，确认真实“粘贴 / 全选”浮层与键盘显示；点击顶部返回，再选“继续编辑”。正常恢复编辑，输入 `.FIX-EXIT-E1` 可见。
2. 再次关闭 Wi-Fi 与移动数据，返回选择“保存后离开”。真实失败留在编辑页，草稿保留；继续输入 `.AFTER-FAIL` 正常。
3. 恢复网络，放弃上述临时草稿。重开详情完整正文等于验收前 baseline，原字段与数组相等。无修改进入预览又只增加一次详情读取；该重开与预览阶段合计 2 次成功详情请求、0 次保存请求。
4. 预览正常显示，取消返回互生首页。Wi-Fi 与移动数据均恢复为开启，诊断采集已关闭，没有遗留未保存草稿。
5. 本段运行日志中构建期断言、Flutter 框架异常、销毁后刷新、布局溢出、未处理异常和原生崩溃均为 **0**。这一结论仅指修复后的冷启动复测，修复前两次真机复现没有被抹去。

证据：[修复后核对](fixed-apk-checks.json)、[选人取消的真实浮层](fixed-picker-cancelled.png)、[继续编辑恢复输入](fixed-input-restored.png)、[退出保存失败](fixed-leave-save-failed.png)、[失败后继续输入](fixed-after-fail-input.png)、[正常预览](fixed-clean-preview.png)。
