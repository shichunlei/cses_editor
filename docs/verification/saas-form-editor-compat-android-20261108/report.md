## 发现并修复的问题

### 原表单人员提及触发语义树异常

原表单加入两名都来帮成员后，Android 语义查询出现 `SemanticsNode.detach` 的节点存在性断言，导致自动化读取的页面树为空。根因为 `AtText.finishText` 在没有点击动作时仍给提及文本创建空点击识别器。

修复 `cses.saas/lib/shared/presentation/mentions/at_text.dart`：仅存在实际回调时创建识别器；保留提及高亮、真实身份和有效点击行为。没有隐藏语义树、包裹额外 Semantics 或改动原表单页面。

使用真实 ExtendedTextField 和多名提及，关闭再启用语义查询，先稳定复现同一断言，再验证修复。新增 3 项回归通过，与旧表单结构化粘贴消费者合计 11 项通过。详见 [修复前失败](mentions-regression-before.log)、[修复后结果](mentions-regression-after.log)、[消费者测试](mentions-and-original-form-tests.log) 和 [静态分析](mentions-analysis.log)。

**真机补充复测已完成：**工作成果原表单通过同一人员页 @ 加入两名都来帮成员和一名领航员；返回后继续输入、收起键盘、滚动，两次独立 Android 语义查询均成功。第二次查询返回 41 个节点，仍包含人员与原表单内容；之后继续输入 `.OK` 并提交成功。本轮框架异常等 5 类运行错误均为 0，详见下方补充验收。

### 历史空栏目被显示为主正文空行

后端旧表单正文包含 todo / expected-effect 区域。此前界面跳过其锁定标题，却把空段投影到主栏目，点击这些空行会把输入写进历史区域，原字段抽离也不会把它当作主文。本轮初次 `.EDITOR-B1` 就实际落在 todo 中；正文未丢失，但显示归属不清。

修复 `cses.saas/lib/modules/mutualism/presentation/orient_result/editor/body_content_codec.dart`：

- 只有模板标题与空白普通段落的历史区域不产生可编辑占位，源结构仍完整保留。
- 有内容的历史区域分别显示为“要做的事 / 预期效果”，与当前主栏目分开。
- 提及、复选项及未支持格式不被当作纯空白静默隐藏；隐藏视图状态、原块 ID、锁定标题和扩展保持往返一致。
- 主栏目新增段落不再继承被跳过的历史区域归属，原字段抽离规则不变。

真机修复后确认“要做的事”独立展示 `.EDITOR-B1`，空“预期效果”不出现；在主段末尾 Enter 新段后保存重开，新增文字正确进入 dailyOrientContent。新增 10 项相关回归，覆盖 ORIENT / RESULT、空区与非空区、隐藏视图、提及、复选项、不支持格式和新增主段归属；4 个相关测试文件共 72 项通过，见 [栏目回归摘要](codec-regression.json)。

### 历史栏目与真实自定义标识避让

最后复核发现，后端真实自定义字段若恰好叫 legacy-todo / legacy-expected-effect，会与历史栏目内部标识冲突。已在同一 Codec 中按源树实际占用稳定分配历史栏目标识：真实自定义字段保留自己的标识和标题，历史栏目仅在冲突时递增后缀；没有冲突时保持既有隐藏栏目标识。原区域及自定义键在编码中继续保留，不修改后端正文协议。新增 5 项回归验证两类记录碰撞、独立隐藏及关闭/清空后的键稳定；与此前栏目测试合计 77 个不同用例通过，见 [标识避让回归](codec-key-regression.json)。
