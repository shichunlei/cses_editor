# SaaS 日导向公司模板适配

以 SaaS 的生产模板为视觉基准。保留正文槽之外的原版布局和素材，把 `cses_editor` 接到对应正文槽。迁移覆盖 ORIENT 和 RESULT 的业务链路。用户只要求规划或审查时，输出对应方案或发现。

产品展示名称统一为 `ORIENT` →“成果导向”、`RESULT` →“导向成果”，入口、编辑、预览和分享使用同一映射。仅展示更名，历史正文与协议标识不改写；原模板标题也按当前记录类型展示。

先读两仓库适用的 `AGENTS.md` 和 SaaS 模块说明。以编辑器仓库的 [迁移方案](../../saas-daily-guidance-migration.md) 为业务依据。核对字段或保存流程时读第 2–5 节，适配模板和入口时读第 6–8 节，验收读第 9–11 节。若技能文件位于安装目录，从编辑器仓库查找 `docs/saas-daily-guidance-migration.md`。

## 1. 追踪实际分发

- 从 SaaS 的 `lib/modules/templates/company/registry/company_template_registry.dart` 和 `CompanyTemplateVariantPolicy` 定位页面。覆盖清单按目标分支重新生成，区分公司映射、部门分流、共享模板的不同品牌、旧一屏版、动态 V2 和随机兜底。正式验收使用生产分发，Debug 指定页用于复现。
- 每项记录公司、部门、选择条件、实际页面类、正文容器、测量方式和品牌来源。固定会话选中的兜底结果，保存、换图和截图时继续使用。
- 可见内容触发官方变体切换时，在安全的编辑提交边界切换，保留正文会话、图片来源和取景。输入合成期间避免重挂编辑器。固定模板放不下全文时，先核对官方长图变体及正文槽扩展能力。原版构图与全文无法兼顾的分支列为待定并暂停放量。

## 2. 在原模板的正文槽接入

- 逐页使用原模板 Widget、图库、主图、相框、字体、头像、问候、日期、裁剪和装饰。沿用原有素材解析和品牌目录。example 的汇丰永盛、成塔服饰、中企云链是编辑交互参考，原版模板始终从 SaaS 侧复用。
- Templates 提供最小公开正文契约，保留旧调用默认渲染。Mutualism 创建唯一活动编辑会话，注入保存、权限、头像和人员等能力。根包通过公开入口提供通用编辑能力，业务和账号留在宿主。
- 编辑挂载一个正文视图。预览、测量和截图消费同一保存修订、实际正文宽度和只读块样式。测量树无输入焦点，截图保留原图片首帧门禁、主图下限和像素保护。保留正文中的富文本和业务行，避免摘要和聚合数组造成重复展示。
- 编辑与预览画布从页面顶部开始并整体滚到透明状态栏下，不在模板外追加状态栏或工具栏高度的顶部占位；模板自身设计内边距保留，顶部悬浮操作独立留在安全区。保留键盘菜单与光标避让。公司 Logo 在编辑时隐藏，保存后预览和分享显示原素材并按比例铺满画布。正文卡收边由模板负责。
- 验证感悟、自检、自定义栏目和人员业务行均可按需添加。试点曾因本地草稿校验依赖服务模板标记而拒绝自定义栏。检查真实存储与已有草稿的校验规则，覆盖添加、填写、保存和重开。

## 3. 接通日导向业务链路

- 从列表或现有业务入口传完整记录快照，按方案区分新建和已有记录。通过现有保存用例提交，创建省略正式 ID，更新使用后台 ID。用同一正文修订生成 `bodyContent` 和兼容派生字段，保持字段名、显式 null、引用类型和去重规则。
- 保存成功转为只读并刷新对应业务入口。失败保留编辑和重试。选人、保存、分享等异步回调复核页面、记录、账号、企业及会话身份。分享成功沿用 SaaS 可信回调和业务回写。
- 覆盖首页、待办、列表、月记录、详情、复制、互动和分享。保持旧版及共用模板调用的原行为。真实接口字段、历史缺失正文、正式 ID 和旧版改写后的正文一致性在 PRE 联调确认。
- 实施前核对依赖声明、锁定和实际解析。生产构建使用可获取的固定来源。涉及块协议时执行仓库规定的 BlockCraft 核对流程。

## 4. 验收与交付

1. 对照图固定模板分支、设备宽度、字号、作者、时间、图片、取景及等高正文。单独标注正文槽、悬浮操作和已确认的 Logo 规则，对其余区域比较几何、素材和图层。
2. 每个生产可达分支至少验收短文与超屏长文。按版式族覆盖窄屏、大字、键盘合成、换图、取景、图片失败和长图页脚。真机验证保存正式 ID、重开、预览和分享。
3. 首批可用汇丰永盛一屏/V2、成塔服饰一屏/V2 和中企云链跑通，再覆盖爱能智亚变体、其他公司、部门与兜底。逐项登记实现、自动化、截图和未验证范围。离线截图仅证明试点结果，SaaS 还原以实际宿主对照为准。
4. 在所属包格式化、分析并运行目标测试，公开接口变更同时验证旧调用方。按仓库规范归档验证记录并运行 `git diff --check`。
